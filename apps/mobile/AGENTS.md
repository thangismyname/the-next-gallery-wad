## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Navigation & Routing

- Use **Expo Router** for all navigation. Routes live in `src/app/` — every file there is a screen, `_layout.tsx` files define navigators. Keep non-route code (components, hooks, utils, features) outside `src/app/`.
- Non-route code lives under `src/` with path alias `@/*` → `./src/*`: `features/*`, `components/{ui,shared}`, `hooks`, `lib`. Consume shared logic from `@tng/shared` (services/types/stores/utils/i18n) instead of duplicating; keep `@tng/shared` free of web-only code (no `lucide-react`, DOM, `localStorage` without a guard).
- **Route files are thin**: `src/app/(tabs)/albums.tsx` = `export { AlbumsScreen as default } from "@/features/albums/AlbumsScreen";`. Screens, their components, hooks and stores live in `features/<name>/` (same names as web `frontend/src/features`). `hooks/` only for hooks used by several features.
- **Auth routing**: root `_layout.tsx` uses `Stack.Protected` (`(tabs)` when signed in, otherwise the root-level `welcome` (signed-in group has `redirectTo="/welcome"` → sign-out / cold start lands there; screen order alone is NOT enough) → `auth` (sign in / sign up tabs, `?tab=register`, back button when pushed) / `forgot-password` screens — keep them at the root, not in a group without an index route, or `/` becomes unmatched) and keeps the splash screen until fonts + session are ready — no redirect effects.
- Import `Link`, `router`, and `useLocalSearchParams` from `expo-router`.
- Docs: https://docs.expo.dev/router/introduction.md

## UI (react-native-reusables = shadcn/ui for RN)

- `components/ui/` holds **only** react-native-reusables components (add with `npx @react-native-reusables/cli@latest add <name>`); custom shared pieces go in `components/shared/` (`GlassPanel`, `GlassButton`, `GlassMenu`, `FilterField` = the muted list-filter box with ✕ — use it instead of a hand-made Search icon + TextInput; Spotlight keeps its own glass `features/search/components/SearchField`…). Glass surfaces = `GlassPanel` (Liquid Glass iOS 26+ / blur older iOS / translucent card Android) — they need content behind them; a panel whose children use `flex-1` needs `<GlassPanel fill>` (it wraps children in extra views — without `fill` a `flex-1` child collapses to 0 height); controls on glass use translucent fills (`bg-background/60`, `bg-foreground/10`) instead of solid colors.
- Style with NativeWind `className` and the theme tokens (`bg-background`, `text-muted-foreground`, `border-border`, `bg-primary/90`…). **No hex colors in components.** When a JS color value is unavoidable (navigation theme, `android_ripple`, BlurView), use `useTheme().colors` (`hooks/useTheme.ts`).
- Tokens: `global.css` (HSL triplets, mirror of web `frontend/src/index.css`) ↔ `lib/theme.ts` (JS copy) — change both. Dark mode follows NativeWind's color scheme; the user's choice system / light / dark = `hooks/useThemeMode` (zustand persisted `tng.themeMode`, applied in the root layout by `useApplyThemeMode`, chosen in the account sheet → Appearance).
- `<PortalHost />` in the root layout is required for Dialog / DropdownMenu / Tooltip.
- Always render text with `@/components/ui/text` (not RN `Text`): it maps `font-heading` / weight ≥ 500 to the right font file (`lib/fonts.ts::fontClasses`). Fonts = same as web: Product Sans (body, proprietary, git-ignored — missing files resolve to an empty module in `metro.config.js` → system font) and DFVN Basteleur (headings, committed); **Japanese UI** → Zen Kaku Gothic New (body) + Zen Old Mincho (headings) (OFL subsets, `.ttf`): RN has no per-glyph fallback between custom fonts, so `Text` / `Input` switch family with the language (`useJapaneseFonts()` → `fontClasses(className, japanese)`).

## API, auth, data

- **Env**: `apps/mobile/.env` (git-ignored, copy `.env.example`): `EXPO_PUBLIC_API_URL` (in dev a localhost/LAN host is swapped for the Metro host by `lib/config.ts`, so a changed Mac IP needs no edit; a real domain is kept), `EXPO_PUBLIC_WEB_URL` (password-reset emails link to the web reset page).
- **Auth** = Better Auth + `@better-auth/expo` (`lib/authClient.ts`): session cookie + cached session in SecureStore, OAuth via the `tng://` deep link (backend `expo()` plugin). Use `useSession` / `signOut` from `features/auth/session.ts`; auth calls live in `features/auth/authActions.ts` (return an i18n error key or null). Never store tokens by hand.

- **Forms**: react-hook-form + zod; zod messages are i18n keys, translated in `features/auth/components/FormField.tsx`. Auth strings live in `auth.*` of the shared locales (also used by the web).

- **Tab bar on scroll down**: iOS shrinks (native minimize), Android hides (`features/navigation/tabBarScroll.ts` store → `NativeTabs hidden`, fed by `useHeaderScroll` + `WorkspaceScreen`, reset on focus; Moments passes `hideTabBar: false`; applied on **Android only** — iOS 26 shrinks the bar natively instead, `minimizeBehavior="onScrollDown"`). ## Responsive (phones, iPad, Android, foldables, landscape) — apply to every new screen

- `app.json` `orientation: "default"` (rotation allowed; iPad multitasking needs it). Never lock a screen to portrait.
- Size by **window width**, never by device model or `Platform.isPad`: `hooks/useLayout.ts` → `width`, `height`, `isTablet` (shortest side ≥ 600), `isLandscape`, `formWidth` (forms / cards: centered, ≤ 420 phone / 460 tablet). `useWindowDimensions` updates on rotation, iPad split view / Stage Manager and foldables opening.
- Always respect **all four** safe-area insets: landscape puts the notch / Dynamic Island on the left or right (`useTabContentInsets()` returns `left` / `right`; header, TabScreen, Gallery and the back button already pad them).
- Grids: columns from width (Gallery `galleryColumns`: cells ≈ 130pt → 3 on every phone in portrait, 5–10 on wider windows). Don't scale a phone layout up.
- Android has no real-time blur: glass falls back to translucent solid surfaces — check both platforms (`npx expo export --platform ios --platform android` bundles both).
- **Lightbox** (`features/gallery/lightbox/`): rendered through `<Portal name="lightbox">` (root PortalHost → covers the tab bar). Open/close = a "ghost" image flying between the grid tile (`MediaTile` measures itself, `registerTile` map → `getTileRect`) and `geometry.ts::fitRect`; it stays until the opened image has loaded (no flash); off-screen tile on close → shrink + fade. **No FlatList / per-page gestures**: `useViewerGestures` = one pan (mode picked on activation: zoomed → pan photo, horizontal → page, up / info open → info sheet, down → dismiss) + pinch (focal math) on the outer detector, double/single tap on the inner one; everything is shared values (`ViewerValues`), React only hears results (page changed, dismissed, zoomed in, dragging, info open, hi-res). Only prev/current/next `LightboxPage`s are mounted (memo, positioned from shared values; index + offset swap in the same frame → no jump). Chrome: single tap / zoom-in / dismiss drag hide it; glass hides via `visible` (`useGlassVisibility`: native dematerialize + content fade — never opacity, never slide); backdrop black without chrome. Drag up → `InfoSheet` (photo lifts + shrinks above it): metadata · AI content tags (17 categories + "oi.*" labels with %, ≤4 dashed below-threshold; names/icons `features/studio/useTagCatalog` + `tagCatalog.ts`, mirror of web) · YOLO objects (emerald, faded below `YOLO_SEARCH_MIN_CONF` 0.4) · personal labels · albums containing · similar photos (4-col grid — not a horizontal strip, it would fight the page swipe; tap → jump if loaded) — data via `lightbox/useMediaDetails` only while open, AI colors `lib/aiColors.ts` (= web; tag chips colored by group via `@tng/shared` `tagColor` → `TAG_CHIP`). The sheet's content scrolls with the **same pan** (no nested ScrollView): sheet + content are one track (`info` for the first `INFO_DRAG`, then `infoScroll` up to `infoOverflow` measured by the sheet), release while scrolled → `withDecay`; dragging down scrolls back then closes. `display` image, original beyond 1.8× (HEIC → `fullUrl`); neighbours prefetched. Video page mounts one expo-video player for the current page only, **no native controls**: the video fills the page box like a photo (`fitRect`) and zooms like one (pinch / double-tap; Android `surfaceType="textureView"` so the transform applies); `lightbox/VideoControls` = screen level above the action bar (not inside the zoomed page), shown with the chrome (tap the video): seek · play · time · 0.5× / 1× / 2× · mute + volume · fullscreen = the **system player** (`openNative`: native controls on first, then `enterFullscreen()`; `onFullscreenExit` → back to ours — without native controls the system fullscreen had no exit button) (RNGH Tap / Pan so they beat the viewer gestures); player + volume / speed via `videoPlayerStore`. Web = `LightboxVideo` + localStorage `tng.videoPrefs`. Actions in `useMediaActions`: favorite / trash patch every cached gallery list optimistically; share = original downloaded to cache (expo-file-system `File.downloadFileAsync`) → `expo-sharing` system sheet (in-app send to friends later, synced with web); save = `expo-media-library` **next API** (`requestPermissionsAsync(true)` + `Asset.create(uri)`; the old `saveToLibraryAsync` throws at runtime). Top bar: ✕ · date · ♥ · ⋯; bottom bar: Edit (placeholder) · Download · ⓘ · Trash. The ⋯ menu = `gallery/components/MediaMenu` (caller items e.g. Share + "Add to album ›" (`albums/useAddToAlbum`: own/editor manual albums) + "Labels ›" (`favorites/useLabels`: one photo = toggle with checks, several = add)); sub-pages swap inside one `GlassMenu` (`contentKey`, `maxHeight` scroll).
- **Multi-select** (`gallery/useDragSelect.ts` + shared `useSelectionStore`): hold a tile 300 ms (pan `activateAfterLongPress`) → selection mode, keep dragging for a range; in selection mode a sideways drag from a tile range-selects (from a selected tile = deselect), vertical still scrolls. Tile rects are measured once per drag (`registerTile` map), list `scrollEnabled={false}` while dragging, `swallowTap()` drops the Pressable tap fired on release. Tap toggles; day headers get Select/Deselect. UI: `SelectionHeader` (✕ · "N selected" · Select all) replaces AppHeader; `SelectionBar` (Share 1 photo only — expo-sharing takes one file · ♥ all/none · save to Photos with progress · Trash · ⋯ `MediaMenu`) replaces the tab bar (`NativeTabs hidden` while `isSelecting`). Leaving the tab (useFocusEffect) / Android back exits. Batch actions: `useMediaActions` `setFavoriteMany` / `moveManyToTrash` / `saveManyToPhotos`. Finger within 90pt of the top (below SelectionHeader) / bottom (above SelectionBar) edge → auto-scroll (rAF loop, `scrollToOffset` non-animated, speed ∝ depth², ≤22pt/frame); tile rects are kept in content coordinates and re-measured every 120 ms while scrolling so newly mounted rows are hit-testable.

## Upload + Camera

- **Upload queue** (`features/upload/useUploadQueue.ts`, zustand, global, not persisted): `enqueue([{ uri, name, type, preview }])` → batches of 8 files per `POST /gallery/media` (`services/upload.ts::uploadMediaFiles`, RN FormData `{ uri, name, type }`, XHR progress via `mobileHttp.upload`), 2 requests in flight. Backend allows 30 upload requests/min → never one request per file. 429 → items back to `queued`, resume after 20 s; a 4xx on a batch → its files retried one by one so only the bad file fails (`upload.badFile`); network error → `upload.networkError`, "Retry" in the pill. Gallery is invalidated (debounced) as files land. `describeFile(uri, { name, type, video })` fills a missing name / MIME.
- `UploadStatus` (rendered once in `(tabs)/_layout.tsx`, above the tab bar (`tabBarSpace`), hidden on `/camera`): glass pill with preview · "Uploading 3/10" · overall bar · retry / close; disappears 2.5 s after everything is done.
- **Pick**: header + menu → `pickAndUpload()` (expo-image-picker, multi-select ≤100, photos + videos, iOS `preferredAssetRepresentationMode: Current` = original HEIC/MOV with EXIF so the backend reads the taken date). Header + → "Take photo" navigates to `/camera`.
- **Camera tab** (`features/camera/`): expo-camera `CameraView` mounted only while the tab is focused (`useIsFocused`), full screen under the tab bar; modes Photo · Video · **Moment** (tap = photo, hold = video ≤ `MOMENTS_MAX_DURATION` → `MomentReview`: caption → upload + `createMoment` circle; iOS runs Moment in camera mode "video" (photo output stays bound), Android binds photo OR video so a hold switches to "video" and waits for `onCameraReady`) (video asks for the microphone, records muted without it), flash off/auto/on (photo) or torch (video), grid, self-timer, **aspect ratio** (`RatioFrame` mask; photos cropped to exactly the framed area with `expo-image-manipulator` — `cameraFrame.ts` maps the frame through the "cover" preview; videos are never cropped), pinch zoom, double-tap flip, prefs persisted (`useCameraPrefs`, `tng.cameraPrefs`), `ShutterButton` (white/red disc, amber ring = Moment, red square while recording), recording timer. `useCameraCapture` sends every photo/video capture straight to the upload queue; the thumbnail shows the last shot + its upload state (tap → Library). Permission card (`CameraPermission`) → `Linking.openSettings()` once the system won't ask again. Permissions text in `app.json` plugins (`expo-camera`, `expo-image-picker`).
